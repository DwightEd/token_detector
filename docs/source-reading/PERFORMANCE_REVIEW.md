## 当前缺陷与允许的模块

统一模型本身并不阻止组合；V3真正的输入限制是只读取full gap。R4的local／route信息没有进入V3。两者还分别有窗口／片段聚合或潜状态借用的问题。另一方面，budget→prizes和金额错例说明，现有gap未必携带需要的语义反证；只改读出不能保证补出信息。

用户允许增加模块，更新后的优先方向如下：

1. **先运行固定的R4＋V3融合基线。** 用同token成对分数进行预先固定的等权秩融合，避免把R4与V3不同尺度直接相加；单独保留R4和V3结果。它检验互补性，是工程基线，不宣称新语义机制。各自AUROC不能推算融合AUROC，也不按最终标签为不同任务扫权重。
2. **补来源支持性核验模块。** 给冻结基础模型看来源和原回答的确定性句子单元，输出支持性判断、来源引用和字符位置。引用／offset可程序核验，但引用存在不证明蕴含关系，模型判断不是gold。先覆盖所有句子，不能只检查R4/V3分歧处，否则可能漏掉共同FN。
3. **保留局部与原token证据。** 让local/full、route和V3作为独立可审计信号，定位“已有信号被压低”的问题。融合若救回Acc却扩大标题/million误报，必须同时报告，不能只展示成功例。
4. **显式算术作可选诊断。** 对原回答中解析无歧义的等式用精确算术检查；不把数值出现、等式正确当作来源支持性证明，也不自动把所有操作数当错误token。复用现有有限语法函数，未知情况保持unknown，不重建关系正确性oracle。

固定秩融合的唯一直接数学依据是统一序尺度，不能推出AUROC必升；核验器引入的是冻结模型的语义能力，也不提供无条件事实保证。允许多个模块，仍需用完整对照判断收益来自哪里。

## 下一轮最少比较集合

R4、V3、固定融合、核验器单独、融合＋核验器。必要时再对新增local或算术信号做删除对照。核验器单独是强对照，避免把其现成能力归到融合上；允许任务专用配置，但配置选择规则须在最终评价前冻结，不能把当前表格逐行挑赢家伪装成新方法。

主目标AUROC≥0.8，逐任务列出，不能用平均值掩盖低分任务；同时报告AP及固定预算FN/FP。已查看数据继续保留为开发证据，现成而尚未用于开发的标注数据或保留测试部分可直接承担最终评价，无需先自建数据集。
