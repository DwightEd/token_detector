# GitHub Tests 的仓库脚本导入错误

GitHub 接收 main 分支提交后，`.github/workflows/tests.yml` 会自动触发 Tests。推送成功只证明提交已接收，工作流随后单独执行；失败会触发 GitHub 的通知邮件。

实际查阅的[最新失败运行 #24](https://github.com/DwightEd/token_detector/actions/runs/41563596975)及[较早运行 #19](https://github.com/DwightEd/token_detector/actions/runs/41522551043)均在安装依赖、安装项目及两个 CLI 帮助检查成功后，因同一收集错误退出：

```text
ERROR collecting tests/test_research_memory.py
from tools.research_memory import claim, finish, fingerprint, inspect_run
ModuleNotFoundError: No module named 'tools'
```

CI 切换到 RUNNER_TEMP，并用 importlib 模式测试已安装的包。`tools/research_memory.py` 是仓库维护脚本，未列入安装包；原测试依赖从仓库根目录导入它，因此在这个隔离环境中收集失败。此前的针对性安装包检查没有运行这项测试，未覆盖完整 CI。

修复只改变该测试的加载方式：从测试文件位置定位唯一的仓库脚本，用 `importlib.util.spec_from_file_location` 加载，并把两处 monkeypatch 改为操作加载的模块对象。没有把仓库根目录加入 sys.path，没有跳过该测试，也没有改变检测器、研究计算或原失败记录。原 CI 仍在项目目录外运行完整 CPU 测试。

独立静态审查检查了模块加载及 monkeypatch 的作用范围，并扫描 61 个测试文件，未发现其他同类仓库目录导入问题。测试前后还应核对整个安装包文件身份，完整的本地命令、日志及源码哈希保留在 `outputs/ci-repair-20261103/`。远端通过与否必须查修复提交自身的 Actions 运行，不能由本地结果推断。

根 AGENTS.md 已补充要求：代码推送前从项目目录外运行完整安装包 CPU 测试；推送后检查该确切提交的 GitHub Actions 状态。局部测试通过不能替代完整 CI。

隔离复验另发现本地 Windows 并发创建目录时的路径别名问题：Python 有时把 `C:\...` 返回为 `\\?\C:\...`，原相对路径检查将同一位置误判为越界。修复仅为比较建立 DOS/UNC 别名键；所有哈希、打开和写入仍使用实际 resolve 后的路径。不同盘符、共享目录、旁系路径及真实符号链接越界仍被拒绝。没有改动运行指纹或检测算法。

修复后的仓库工具回归在项目目录外实际得到 **40 passed，0 skipped，0.90 秒**，包含原八线程竞争、跨平台的 DOS/UNC 别名、实体 I/O 路径保持及真实符号链接越界检查。检测器的 126 个安装包成员和原 wheel 在检查前后逐字节保持一致。详见 [修复及回归证据](../refine-logs/ci-repair-20261103/archive-manifest.json)。

本地 Windows 完整 CPU 测试曾达到显式 600 秒上限，被记录为未完成；没有全套通过计数，不能写成全套通过。此前包装脚本未保存超时异常中的部分 pytest 输出，这一证据限制也保留在回执。远端完整 Linux CI 的最终结论仍须核对本修复提交的运行。
