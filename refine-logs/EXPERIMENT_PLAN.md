## 主张与证据层级

| 待检验主张 | 最少需要什么证据 | 哪种结果不能支持它 |
|---|---|---|
| C1：隐藏待核值的来源重建能减少观察模型追随错误前提 | 同一自动框架、来源、模型、解码下，盲条件比暴露值条件更常恢复正确归属；同词袋交换与来源缺失控制符合预期 | 只遮蔽一个已知错误词；只有字符串不相等；只有直接核验器能力提高 |
| C2：这种新观测能改善跨合同检测 | 完整人口、冻结投影/评分/unknown 行为后，六任务与强直接核验比较；归属模块删除导致可解释退化 | 18 个探索案例改善；挑任务最好方法；改变标签或删除前几个 token |

反主张必须排除：收益仅来自更强模型/更多调用，自动提议只覆盖简单短句，数字执行误把正确算式当完整命题支持，以及标签粒度或观测后端造成假改善。C1/C2 均为假设，普通 QAG 与 CoVe 不是本项目的新贡献。

## B0：输入、先前证据与执行资格

- 复用已完成的 FN/FP 与 31 条先前实验记录；不重跑固定等权、不重报计数作为新发现。
- 数据与观测身份审计已完成。RAG 原权重分片/后端仍未完全认证；新 Qwen-3B NF4 是新观察器，不是历史 BF16 Llama-8B 重放。
- 固定 18 答面板：15 个已知案例、3 个按输入 ID 哈希选取的结果未知控制。完整未标亮输入进入自动流程；评价材料另存，评分/观察阶段不读取。
- 纯合同测试检查值隔离、精确原文定位、引用成员性、歧义、坏输出保留与可恢复缓存；这些不是效能实验。
- 自动提议允许程序将唯一的精确原文片段对齐到字符位置。显式位置错误不回退修补；重复片段无消歧则无效。该步骤不证明语义角色正确。
- 解码在首次模型运行前固定：贪心，完整输入上限 4096 token，提议输出 1536、各观察输出 256。1536 是预先的序列化容量修正，不能在看到评价结果后按案例增加。达输出上限单列为覆盖受限；无效 JSON、无提议、缺槽位和 unknown 全部保留。

成功门：包可安装、中央入口可调用、原输入人口完整、模型/代码/协议身份封存、资源准入通过。工程失败不计作语义假设被证伪。

## B1：自然错例上的自动观察资格（必须先做）

共享自动提议器只看完整回答，不看来源或人工错误位置。同一框架的每个槽位产生 direct / blind / leaky 三路调用：

| 条件 | 看见什么 | 决定性检查 |
|---|---|---|
| direct 强基线 | 来源、完整声明、自动选择的槽位 | 在相同调用/输出上限下是否已经解决问题 |
| blind | 来源、确定性掩码声明、槽位角色 | 不接收原值、整段回答、提议器生成的问题或选中位置；原值不同而掩码合同相同，输入字节必须相同 |
| leaky 暴露值对照 | 与 blind 相同的合同，加显式声称值 | 是否更追随错误值；它不是新检测模块 |

此块只封存观察，不临时拼出 token 风险分数。封存后才打开 evaluation_only，逐例报告自动覆盖、源证据忠实度、关系归属、无依据支持、正确内容被否定和 unknown。未知与未提议项保留在全 18 答分母，另报条件覆盖；不得只展示成功槽位。引用存在只能验证文本成员性，不能证明蕴含。

重点考察账户替换、coverage 与 billing、第一/第二机器人的事件、False/None、错误否定来源有信息，以及正确 80.8 推导。缺原始比较问题、角色/单位不明确或需要尚未提供的执行器时，合理行为是 unknown。

停止/转向：无自然覆盖时先判定提议/序列化合同失败；三路都无法恢复时判定观察能力或欠定问题；direct 同样好时优先保留简单基线，不包装 blind 为创新。不同失败层级分别记账。

## B2：关系机制与反例控制（B1 能用后）

预先构造并单列 actor/年份/账户归属交换、无关键证据、同名无关实体、显式 False→None，以及相同算术结果但错误账户的最小控制。控制生成不使用新模型输出或测试标签选成功例；语义可核验的构造小世界与自然原数据分开报告。

指标：按构造关系的响应一致性、错误暴露值跟随率、支持/冲突/未知覆盖、合法推导误报；使用同样自动提议流程，同时报告上游失败。相同词袋但关系改变时应改变结论；证据缺失时应允许 unknown。

理论保证仅限：给定同一掩码框架/角色/来源时盲调用输入与被隐藏值隔离。它不证明上游选择无偏、语义无泄漏或模型正确。若后续使用类型化执行器，条件证明也必须以叶节点出处、角色、单位正确绑定为前提，不能以执行成功代替事实正确。

## B3：检测器合同与完整六任务评价（B1/B2 通过后）

必须在运行前另行冻结自然覆盖策略、blind 重建结果的比较器、全 token 投影、重叠/未覆盖/unknown 评分行为和成本；目前这些尚未定义，不能把观察输出叫作已完成检测器。

- 人口：RAGTruth QA/Summary/Data2txt、FRED FinQA/TATQA、HalluRAG 发布 answerable/target-available 891 答；Hallu 全部与不可用来源组继续单列。
- 系统：原 R4、原 V3、同一新观察模型的 direct alone、最终选定的新模块 alone；只有确实定义必要组合时才加原主线+模块和删模块消融。拒绝的等权仅作既有历史控制。
- 主要指标：每任务完整原轴 AUROC；同时 AP、固定预算 FN/FP、全人口覆盖、unknown、延迟和输入/输出 token 成本。保留发布标签粒度，不改 gold；明确句级广播等限制。
- 不确定性：按来源/文章聚类的成对 bootstrap，固定种子；来源等权是另外的估计量，不与原 token 汇总点值混淆。只变评价置信区间，不重复采集模型观察。
- 达标：六任务分别报告点值和区间；点值均 ≥0.8 才能说达到点值目标，若区间跨阈值必须直说。不以任务最好包络代替一个冻结系统。
- 当前六组已被查看，只能支持探索结论。另找尚未接触的现成标注集/原始来源承担确认；不把已看数据重切分成“未接触测试”。

消融只回答必要问题：去值隔离（leaky）、换成同预算 direct、去来源证据/去角色的构造控制；有执行器时再做去执行器。每删一个模块，必须能说明它影响的失败类型和保住的正确内容。多一层模块没有可识别收益便删去。

## B4：跨数据差异与解释边界

已知描述复用：金融数字密度约 20% 而 RAG 约 2–3%；金融 scorer 单元更长；Data2txt 为 Python 字面量；Hallu 前导空格与生成器完全混杂。它们不是 AUROC 差异的因果解释。

在新冻结观察器内，按自动提议覆盖、关系/数值类型、证据长度、原问题是否存在、礼貌开头与事实否定分层；不按表现挑分层边界。条件不足或组间没有共同支持时只报告关联。Q0 使用同回答增加/删一个前导 ASCII 空格及内部空白对照、精确字符映射；不删除原任务 token，也不将新观察器结果外推成旧缓存的原因。

完整观察器×生成器配对与第二骨干验证是后续确认块。优先解决主方法与 direct 的差异，不先铺开无上限模型矩阵。

已看错例用于假设与事后诊断；真值不进入提议/求证，不训练，不按 gold 搜权重/阈值。完成一轮后只推进下一条能区分解释的问题，避免回到已知现象复述。
