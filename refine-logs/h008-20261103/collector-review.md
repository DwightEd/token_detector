## Findings requiring repair

1. **Completed request files are not held immutable while later requests execute.** In `qualify` lines 211–228, `immutable` contains the initial plan/protocol/identity/request files only. Once a request finishes, its `backend_raw.json`, `response.json`, and child `seal.json` are never added to a persistent snapshot or verified again. A later backend call can alter an earlier response or seal. The final root `_seal` at line 234 hashes the new bytes and can endorse them, whereas `complete.json` is calculated from the old in-memory `responses`. Thus a supposedly complete root can disagree with its raw request evidence. Keep the exact completed-child member inventory and hashes, including the original child seal bytes/hash, after each completion. Validate every completed child before later calls and immediately before final export; compare persisted response/raw data with the validated in-memory values or rebuild the final reduction from validated persisted values. Test modification of a prior response, raw observation, and child seal from a later fake call. Reject the mutation and leave no valid root completion/seal.

2. **Path containment and exact inventory are checked too late for new artifact members.** Initial/final `rglob(...).is_file()` and `_seal` hash each discovered file before `data.verify_seal` performs containment checks. A backend-created extra file is silently incorporated into the final seal; an extra file symlink can cause reading an outside payload before rejection. A replaced immutable file can likewise be hashed without a fresh alias/containment gate. Admit the full current tree, reject file/directory aliases, and validate the exact allowed member set before any artifact hashing. Use the established inventory/member/snapshot pattern, with the allowed tree expanded only for the expected completed request files and final completion file. Test unexpected files and a contained-path name resolving outside the run before any hash of that payload. This also supplies the inventory needed by finding 1.

Both gaps were sent to root immediately during review. They concern evidence integrity, not a demonstrated numerical error in the real backend.

## Contract tightening recommended

- Enforce one fixed `eos_token_id` over all 32 preflights, and identical `prefix_ids` for the two candidates of each query. `_metadata` validates each individual framing but not these cross-candidate invariants. The real deterministic frozen helper supplies them, but a variant/fake backend could otherwise return two internally consistent observations conditioned on different prefixes or termination events and still reach two-candidate normalization.
- `_response` validates forward/input/target/output counts and duration, but does not require or type-check `resource_admission`, `peak_cuda_allocated_bytes`, or `peak_cuda_reserved_bytes`. Require the expected device/allocator identity and nonnegative integer peaks if those fields are part of the retained runtime-cost contract. Boolean values should fail integer checks.
- An explicit finite check on `distribution['log_candidate_normalizer']` documents the intended boundary. In the current kernel, finite joint inputs and stable two-term log-sum-exp already make it finite, so this is defensive rather than a current numerical failure.

## Checks that pass

- `_prepare` retains all 48 unique originals, eight source strings, 16 queries, 32 complete-name candidates, and 96 separate response slots. It rejects unsupported frontends before model scoring rather than dropping cases. The frozen input SHA binds the original population; each original sample and prompt/source/response hashes remain in the plan.
- Questions and the sorted two-person candidate pool come exclusively from `kernel.source_queries(sample.source)`. Its function has no response argument. Response text enters only `align_response` and exact slot preservation, and never selects the pool, questions, or model messages. Source grammar validation establishes a narrow constructed-panel contract; it is not natural-data coverage.
- All 32 `validate_completion` results are deep-copied, checked, included in the keyed execution manifest, written with every request and plan, and frozen before the first `score_completion` call. The frozen manifest includes protocol SHA, model identity, installed-source identity, complete messages/candidate, and token framing.
- For P prefix tokens and K candidate tokens, `_metadata` demands `input_ids=P+K` with no appended completion-terminal EOS, targets `K+[EOS]`, and causal prediction positions P−1 through P+K−1. K is nonempty, the EOS is one nonnegative integer excluded from the candidate suffix, and all K+1 target rows are retained. Prefix-internal EOS is correctly allowed. This matches the backend tail-K+1-row contract and includes the first name token and terminal EOS.
- `_response` binds every metadata field to preflight. It requires K+1 finite raw target logits, full-vocabulary normalizers, and log probabilities; verifies raw−normalizer=logp and `fsum(logp)=joint`; rejects positive token logp beyond tolerance; validates declared full vocabulary, `(1,K+1,V)` shape, float64 normalizer label, one forward, zero generated tokens, and finite nonnegative duration. It does not claim that the selected logits alone prove a full-vocabulary normalizer; the separately frozen backend code performs that full-vocabulary computation.
- `candidate_distribution` uses stable two-item log-sum-exp on finite complete-sequence joint log probabilities. The collector requires `log_candidate_normalizer <= 1e-9`, so the two distinct literal-name-plus-EOS event masses sum to at most one up to rounding tolerance. There is no length correction, temperature fitting, calibration, or semantic A/B/C reinterpretation. Reported candidate probabilities are explicitly conditional on the candidate set and are not factuality probabilities.
- Slot risk is exactly one minus its source-only conditional candidate probability. Both slots and every original remain; document max-slot risk is separately identified. Final output explicitly denies token projection, natural-task performance, and promotion.
- Path arguments must be independent, resolved, and unaliased; input basename is `inputs.jsonl`; known annotation/construction-truth protocol basenames are rejected; strict protocol schema disallows label fields. Existing output directories are rejected, so partial runs are retained without implicit resume or retry. A failed backend payload is written before validation. Frozen message mutation is detected. Final exceptions delete `complete.json` and the root seal; the required additions above should extend those protections to all completed child evidence.
