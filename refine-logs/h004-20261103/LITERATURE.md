## 对当前 H004 的判断

**朴素的 typed/path-preserving serialization 是应有的接口基线，现有材料不足以支持顶会方法新颖性。** 上表文献分别覆盖来源核对、表格表达、三类推断、标签偏差和可检查推理。把标准三值语义写进提示词、加类型标签、对全部标签排列求平均，都不能单独构成新的事实判定原理。这是本轮从文献作出的定位判断，不是论文可录用性预测。

`D(R(T)) = T` 只证明受支持语法下的类型树保留。它不证明字段名的现实含义、不证明来源可信，也不证明观察器正确理解该表达。原文 JSON 往往已经显式区分 null 与 false；H004 检验的是将其变得更容易读取是否有作用，不能预先声称恢复了原输入中不存在的类型信息。原文拒绝、重复键、数字保真与全部输入覆盖属于实现正确性义务。

`null → 未报告` 还需要来源合同成立；有些系统把 null 用于不适用、未收集或隐藏值。对本次已声明的开放世界合同，未知不能通过否定变成已证实的假。这个约定应显式固定，不能以标签结果修改。

A/B/C/D 的表达×规则交叉对照有判别价值：它能区分“表示使结构更可读”与“只因新增提醒规则改善”。它不识别原生成模型的致错机制，也不产生完整 token 检测器或自然数据总体收益。应保留全部六种标签分配、原始词表质量、超长和解析拒绝，不只展示最优标签映射或成功子集。

## 可能继续追问的机制，尚未验证

若 H004 通过资格门槛，较有研究价值的下一问题是：**来源的类型/绑定结构能否支持无需标签调参的局部反事实证据约束，进而把回答 token 的错误判断绑定到可核查的依赖路径？** 例如仅交换两个字段的归属，或把一个明确布尔值替换为未知，要求判定只在依赖该字段的命题上按预先规定的方向改变；与无关字段的编辑保持稳定。解析保真、命题到字段的绑定是否可靠、未知传播及 span 覆盖率要分别核验，无法绑定时明确 abstain。

这里潜在的区别在于“类型化来源编辑 → 局部命题依赖 → token 证据响应”的可反驳约束，而非增加一种序列化格式。它仍可能与既有反事实验证、metamorphic testing、natural-logic/provenance 方法重叠，必须另做近邻检索和独立确认；本轮不能宣称新颖、有效或天然无监督。也不能把先前自然覆盖不足的有限证书换名重试。算术执行继续作为独立假设，不混入 H004 以掩盖失败。

全程约束：真实标签只在方法、参数、阈值、人口与分数封存后用于最终评价；已看过的人口保持探索性；不得拟合 R4/V3 权重、选择最佳排列或按标签路由。以上文献用于界定基线和设计反例，没有授权改动现有方法或启动推理。
