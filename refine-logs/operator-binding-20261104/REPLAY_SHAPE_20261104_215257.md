# H018 同形状 MLP 重放：独立审查后的预算修订

时间：2026-11-04 21:52:57，Asia/Shanghai。保留21:48原稿和21:51补充。本页优先修订“局部重放数值身份”与相应计费，不改变主 scope、符号、原R接口或 NOT_ADMITTED 状态。

原 native MLP 可能处理完整 N 行，局部 counterfactual 只处理 T 个原 prechoice 行；即使权重与算术精度相同，GEMM形状不同也可能产生浮点差异。因此不能未经证明就把原 N 行的 native MLP输出与T行counter作精确差，再声称所有差都来自干预。

**拟采用唯一方案：两个分支均以相同 T 行形状重放。** 每层保存真实 native MLP输出的T行，再作以下4个局部官方MLP调用：

1. 同形状 reference：`MLP(norm(x_mid_R))`。
2. 来源入边移除：`MLP(norm(x_mid_R−m_source_R))`。
3. 固定norm-sham：同形状、同精度、预定随机方向。
4. 独立走同一 counter路径的 m=0 no-op。

source/sham 的 δ 均使用该同形状 reference 减相应分支，先消除两侧GEMM形状差。reference 对真实 native MLP输出的全坐标误差必须独立通过**运行前冻结**的数值身份门；m=0对reference也必须先过独立no-op门。不能看原数值后放宽容差，不能把未通过的reference冒充native，更不能将其解释为MLP warning。具体容差和累积D误差的资格仍需代码前审查，本页不默许复用旧attention门作为新MLP门。

两条原R的额外MLP调用上界由先前192修订为 **2例×32层×4=256次**；每次批处理该例全部T行。native full forward仍2次，完整head仍每例native/source-removal/sham三次，共6次。对0向量D的head身份可使用同一native输出和无干预原H，不再增加完整head；若需要实际额外head调用，必须先修改预算再claim。reference误差、每个分支的输入行数和耗时完整计入，不能称“零成本”。
