# 第二次修订：完善审计实现，保留未通过的科研门槛

## 不变的问题锚点

**底层问题**：给定提示、来源和已经生成的回答，在保留原始 token/字符位置的前提下，定位回答中不受来源支持的内容，并说明分数的统计含义。

**必须解决的瓶颈**：当前来源删除对比和片段共享可以改善整体排序，却不能据此证明片段内部定位改善，也不能把预测专家责任解释为事实错误后验。

**非目标**：通过改名称、堆模块、增加没有识别假设的公式或反复选择测试集配置，宣称达到顶会水准。

**约束**：先按无监督主线推进，标签只用于冻结后的评价；保留原始 token 轴、冻结 R4 资源和历史失败记录；本轮不启动远端/GPU实验。纯 CPU 数值检查不等于真实检测结果。少量人工标注校准/训练是待用户选择的独立分支，不混入无监督结论。

**成功条件**：完整可追溯的代码解释；明确的定义、假设、推导、算法、复杂度和反例；相对最近方法可检验的贡献；在新的自然人类标注错误片段上，跨来源和模型验证局部定位收益与成本，并接受独立审查。顶会接收不是本地证明或审稿模型分数能够保证的结果。

## 一句话论点与目标边界

先证明并量化哪些 pooled-AUC 收益不来自片段内区分，以此筛掉无效方法改造；只有新增语义观测在独立来源支持性标注上改善局部区分，才允许晋升为检测器贡献。**诊断阶段本身不算完成“改进检测器”的目标。** 主标签为 provided-source support，不把世界事实真伪混为同一个变量。

## 文献与新颖性约束

CORTEX 已有参考有/无对比、监督 token 分类与持续性平滑；LUMINA 已有预测分布对照。TPA 是监督 response-level POS 聚合，不作为 token 局部定位基线。新核对的 [USP/SHROOM-Visions](https://aclanthology.org/2026.uncertainlp-main.47/) 已明确研究 informative proxy 到精确跨度定位的脱节；[Temporal Multi-Signal Fusion](https://arxiv.org/html/2608.18115) 已有 NLI/LM/text 序列融合与顺序打乱消融；[SHAM-Bench](https://arxiv.org/html/2610.27370) 已有跨任务 span 基准。故“指标粒度重要”或“加时序结构”都不能单独声明首创。

剩余可能的组合贡献是：固定片段的精确正负对分解 + 交换型专家共享保序边界 + 近期方法的独立人类 RAG 支持性再评价。数学分解本身是基础身份，保序性质也可能是已知混合模型事实；新颖性需要研究问题、实证发现和实用诊断共同支撑，当前未确认。

## 两路线及阶段选择

**A，最小诊断路线（当前执行阶段）**：不增加训练模块，复用原始观测/封存体系；加入 pooled/within/between AUC 精确分解，检查 raw/shared 的局部身份，并在未来新数据上验证。优点是立刻可检验、能揭示无效改造；缺点是不能自行改善 detector，且与最近工作接近。只有新数据带来稳定、可迁移、非显而易见的新发现时，才考虑独立方法论论文。

**B，新增语义信息路线（候选，未实现/未定名）**：将冻结的来源蕴含验证器作为外部观测，在同一个原始 token 轴提供命题支持/矛盾信号。先实现为预算匹配的独立基线，与单独 verifier 比较；不把它与 HMM/Beta 任意拼接成“新方法”。必须找到并验证一个相近 NLI/LLM-judge 方法未解决的失败机制，例如语义保持改写下的支持判断不稳定；若不能优于同预算 verifier 或仅靠其现成能力，取消新方法主张。此路线不提供无条件数学保证；理论只能在明确的 parser/verifier 误差或校准假设下讨论。

当前不选择未经验证的 detector 架构。A 是 B 的审计前置步骤；它是为用户原问题排除假改善，不能偷换成已解决检测问题。

## 已完成的最小代码增量

`experiments.local_evaluation.auc_pair_decomposition` 统计 pooled、同片段和跨片段正负对。每个对子贡献的两倍取整数0/1/2；同分半胜。排序负类并二分查询，O(N log N) 时间/O(N) 内存，避免枚举所有对。返回零对时 AUC=None，并报告 within 对占比。已有 `fullgap_dataset._paired_views` 在解封分数、排除 unknown 后为每个方法附加此报告，不改变方法分数或已有历史文件。

新的 tests 独立穷举核对对数、ties、纯标签/空集、跨回答/不连续身份、大整数顺序，以及评价入口 unknown 排除。理论测试调用生产 cavity/persistent 验证保序、协方差导数、自证据斜率、排列不变、c=0 退化和跨段反转。它们不是自然数据实验。

## 下一轮真实验证协议（待执行）

三个核心块保持不膨胀：

1. **计算正确性**：理论身份、实际 dtype/ties、原 token 轴和封存校验。匹配 eager/SDPA 后端及投影/归一化精度的源效应对照是机制解释的硬门槛。现有历史结果保留并标记后端差异，不重新解释为已排除混淆。
2. **新的人工支持性确认**：冻结当前已探索数据之外的来源，标注 supported/contradicted/absent/uncertain 四类与字符边界；主二元指标事先规定如何合并。选择来源为独立重采样单位。原六组和银标/句转 token 数据只能是开发证据，不能冒充新确认。记录混合片段、纯片段、unknown、独立来源数和标注分歧。
3. **局部改善与新信息**：同预算 raw/shared/一个 sequence/LUMINA；监督 CORTEX 单列表。若做 B，先比较 verifier alone，来源语义保持改写、匹配长度的删除/替换负对照，并在另一 backbone/task 上确认。只改善 pooled 而不改善预先定义的局部目标，不能晋升为新局部检测器。

当前已有 `paired_span_differences` 是**对数加权点估计+来源 bootstrap**，不是来源等权宏平均。新主实验拟以每来源等权的片段 concordance 为主，必须另行实现并冻结；本轮不把当前函数改名冒充它。AP 单独报告，没有套用 AUC 的线性分解。Span F1/字符边界误差作为不同估计对象的次指标，阈值仅在开发数据决定。

## 明确否定与停止条件

- raw/shared 在相同片段内出现非 ties 数值容差可解释的秩差：先判实现/对齐 bug。
- 新数据不复现全局/局部分离：收缩或撤销普遍诊断主张。
- 最近工作已覆盖同一贡献，且没有新的机制/实证价值：停止独立投稿包装。
- 匹配后端/预算/分段后收益消失：撤销对应机制结论。
- 新语义模块不能优于 verifier alone：不能把拼接宣称为新算法。
- 来源数或混合片段太少：报告不可评价，不能用海量相关 token 对冒充样本量。

当前状态：`DETECTOR_IMPROVEMENT_UNESTABLISHED`、`VENUE_READINESS_UNESTABLISHED`。无伪造评分、无新的 GPU/自然数据结果。外部证据未改变时，重复改文案不能推进硬门槛。


## 本轮独立审查后的具体修正

1. 已修复 fullgap.evaluate 最终序列化漏项：保留原始 metrics 的 units 等键，同时把 pooled AUC 分解写到每方法的最终 metrics，连同输出 seal 一起保存。新增测试走真正 evaluate/JSON 写出；模型、封存输入验证和标签投影使用明确的测试 fixture，未冒充真实数据全流程。

3. 新诊断的段数命名为 known_token_spans / mixed_known_token_spans，避免把排除 unknown 后的可见段数当原始总段数。原始全 unknown/纯片段覆盖仍是未来协议的待实现项。
4. between_spans 严格表示全部跨片段正负对，混合了跨回答/跨来源，不能单凭该项归因于区域借用。它目前是描述性代数补集；若要机制归因必须再按层级分解并控制来源/回答差异。
5. 不修改不可变问题锚点。锚点成功条件中的“错误片段”在本轮操作定义为不受给定来源支持（矛盾/来源缺失），不是世界事实真伪；未来需要外部事实标签时另列任务。
6. 后端核查补正：默认 Observer 文本测量的 eager/SDPA 差异确实存在；但 fullgap_dataset.collect 已记录 backend='matched_sdpa'，并实际调用 measure_responses → counterfactual.observe_responses，让两个世界同走 SDPA。不能用默认 API 的问题否定全部历史 full-gap 实验。每次历史运行仍需其 plan、源码 hashes 和封存观测确认。第一/二轮审查未检查此路径，宽泛的后端混淆判断在这里收缩到可证范围。

当前没有新独立人工支持性标注、没有匹配后端的新 LM 观测、没有经过确认的新颖性差异，也没有实现未来 source-macro 主估计量。它们仍阻止方法升级和 venue readiness。第三次审查只检查本轮代码/定义修复，不应生成通过科研门槛的替代分数。
