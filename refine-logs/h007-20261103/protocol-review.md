# H007 independent protocol review

Static review passed after the findings below were corrected by the implementation authors. No unresolved material launch blocker remains. No model calls, GPU access, old test reruns, or actual `construction_truth.jsonl` access occurred during this review. The generator's source code and declared truth schema were inspected; its generated truth contents were not opened. No production code was edited by this reviewer.

The complete design is 2 relation families × 2 vocabulary instances × 2 source directions × 2 response directions × 3 burdens = 48 original responses. Collection creates exactly two focus cases per response: the complete response and its first deterministic automatic unit. Both cases retain the original source, complete response and pre-generation context; the shared builder changes only the before/focus/after partition. Metadata IDs and factor labels do not enter the model messages. The generator fixes the target first, including its trailing space, and keeps all twelve source fillers fixed as response burden changes.

This yields 96 logical cases × 6 label assignments = 576 logical requests. In the sixteen zero-burden originals, whole and target inputs coincide, permitting 96 exact-request reuses and an expected 480 distinct requests. These are design counts, not claimed execution costs: the collector and CPU reader retain every assignment and reconstruct the actual unique requests, input rejections, token counts, forwarded calls, time, coverage, raw responses and parent completion from the shared scorer. Full preflight precedes the first model forward. The parent/child plans, prepared input bytes, full request roster and exact completion are independently reconstructed on CPU.

The paired contrast is correctly defined over the 24 cells `(family, vocabulary, source_direction, burden)`, with exactly one supported and one wrong-binding response per cell. Let `D[m,b]` be the mean of the eight wrong-minus-supported risk differences at mode `m` and burden `b`. The predeclared primary interaction is `(D[target,12]−D[target,0])−(D[whole,12]−D[whole,0])`. A positive value describes greater preservation of relation separation for the target scope; it is not sufficient alone to establish the mechanism. The zero-burden discrimination, all 24 pair rows, both relation families, vocabulary identifiers and the intermediate burden remain visible. Correlated cells from four lexical scenarios are not treated as independent large-sample evidence.

Four reviewed corrections are present:

1. Evaluation now rejects overlapping observation/inference/construction/output trees before any contents are read. The design must be `inference/plan.json`; the protocol must be external to those trees and cannot use truth/annotation filenames. The collector also rejects `construction_truth.jsonl` as a protocol. This closes the possibility of reading truth bytes through a protocol argument before evaluator freezing.
2. Truth joins now bind source and response SHA256, target boundaries, all supported fillers, the fixed construction rule and `target_benchmark_labels_used=False`, in addition to IDs and source/response-direction outcomes. Same-ID stale or mismatched construction labels fail validation.
3. A final `unchanged()` check now runs after output sealing and verification. It rechecks the initially captured observation seal, source identity, CPU freeze/plan, original inputs/design/protocol and construction seal. A late failure removes the completion marker and final seal while retaining partial diagnostic artifacts.
4. The collector rejects an output nested inside the inference input tree, matching the CPU reader's disjoint-tree contract. A directory layout that the reader cannot evaluate is therefore rejected before expensive model observations.

The reader admits the exhaustive nested observation tree and seal paths before payload hashing/source discovery. It checks exact compatible helper bytes and rebuilds every request/readout before creating its source-frozen CPU plan. Construction truth, including its hash, is opened only after that plan and freeze are written. The final checks preserve the initial observation seal rather than accepting a resealed replacement.

`prepare_observation.py` and `evaluate_finished.py` were also reviewed statically. Both require the same passed 109-file release receipt and exact source/resource manifest. Observation preparation pins the original input and inference-plan SHA256 values, registers that plan, inference seal, generator, design, protocol and launcher as observation dependencies, and never includes or hashes the construction directory. This binds factor metadata before predictions. The generated launcher is derived from the H005 template using checked replacements for the H007 spec/identity/protocol, burden output/log, original inference input and `qualify-designed-focus` entry point. It preserves the same Qwen2.5-3B weights, NF4/FP16/SDPA profile, finite-label six-assignment readout and resource guards, updating only the installed-wheel/CPU-target identity to the new 109-file release. No generated launcher/spec was executed by this reviewer.

The CPU wrapper first requires the registered observation run to be reusable and to match the recorded run ID. It uses the same 109-file release and the actual six-argument `evaluate-designed-focus` API. Its pre-evaluation spec hashes only inference/design/protocol/observation-seal metadata; construction truth is not hashed by the wrapper. The evaluator retains sole responsibility for opening that independent truth tree after reconstruction and CPU freezing. Planned LF normalization of the new Python files is a source-byte identity change; the final canonical bytes must be captured by the release receipt before observation. The archived H006 107-file target, wheel and commit remain separate and do not need a model rerun.

This qualifies a new constructed source-binding × response-burden comparison. It does not establish original-generator causality, natural-task efficacy, BPE-token localization, six-task AUROC ≥0.8, method novelty, or a target-label-selected method. No threshold, prompt, model or subgroup selection is performed by this analysis.
