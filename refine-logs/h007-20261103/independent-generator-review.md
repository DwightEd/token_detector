# H007 生成器与推理材料独立科学合同复核

结论：**未发现阻止当前固定 48 格资格实验的实质科学合同漏洞。** 两个关系族、翻转、负担与焦点范围在所审查代码及已写出的推理样例中一致。无需为本复核改写已生成材料、重跑生成器或增加模型调用。下述解释范围必须随最终结果保留。

本复核只读取 `DESIGN.md`、`generate_controls.py` 和 `inference/{inputs.jsonl,plan.json,seal.json}`。未打开正式 `construction/construction_truth.jsonl`，未读自然 benchmark 标签或预测，未调用生成器、模型、GPU 或 tokenizer，也未重跑已通过的 16 项生成器逻辑检查。对推理文件的行数、字段及哈希作了只读记录，并人工核对覆盖两个关系族、两个词汇实例、两类翻转和不同负担的六条已写出样例。

**关系定义与目标语义。** 比赛来源先明确每场决赛的两名不同参赛者，再明确唯一胜者；两个决赛名称互异。签署来源为每份不同文书明确唯一签署者。故在来源被视为指定事实依据的合同下，交换角色不是“未报告”或另一个可能身份，而是与唯一角色声明冲突。目标没有代词、算术、同人自反比赛或外部常识补全义务。两个关系族都把两项实体—事件断言放在同一首句中；正确端与交换端判断的是同一并列语义范围，不能把它称作已经证明的单原子命题。

例如，写出的 `winner-lex1-s0-r0-b00` 来源指定 Mira Tanswick 为 Virelan Cup 决赛唯一胜者，Oren Pellford 为 Nerowan Cup 决赛唯一胜者；其首句分别使用这两个绑定。`winner-lex1-s1-r0-b04` 只反转来源的胜者绑定，回答首句仍相同。`sole_signer-lex2-s0-r0-b00` 和 `...-s0-r1-b04` 则在同一来源下交换 Nadia Fennbrook/Hugo Valecrest 与两份文书的回答绑定。这些是对公开推理文本的语义核对，不是读取正式真值文件或产生预测标签。

**全因子与词袋。** 推理材料有 48 行、plan 有 48 条记录，声明的因子为 `winner/sole_signer × lex1/lex2 × source_direction(0/1) × response_direction(0/1) × distractor_count(0/4/12)`。代码以固定 `itertools.product` 生成全格，不根据任何模型输出或 benchmark 案例选择模板。每个方向都只是把两个人名在两项事件间对换；比赛参赛者句保持固定，唯一角色句及回答中的人物各出现同样次数，其他词不变。因此单纯词袋无法给出正确端/交换端的区别，source 与 response 两个方向也没有缺一端。两个 lexical 实例是新名字/事件实例，不能解释为两种独立句法模板或广泛改述覆盖。

**来源与回答负担。** `source_facts(...)` 的输出始终与完整 `FILLERS` 合并，burden 不进入来源构造。回答则使用目标首句加 `FILLERS[:burden]`。十二条 filler 涉及独立命名的馆、图书馆、作坊等及物品/活动，不涉及目标人物、赛事或文书，不改变唯一胜者/签署者关系；回答使用的每条 filler 都逐字存在于来源。没有用缺证据、假 filler 或改变来源长度来伪造回答负担条件。四句与十二句使用同一前缀顺序，因此两端的 filler 选择、顺序、位置规则也保持一致。

**焦点与输入隔离。** 目标始终在首部；代码对所有 burden，包括 0，统一保留目标句末一个空格。这样首个自动 `response_units` 范围的边界不因是否存在下一句而变化。0 filler 的完整回答就是这个首单元，所以 whole/target 请求有合理的精确复用条件；这是应计入成本的重复请求，不应删除任何原实例。输入行仅含 `Sample` 文本与常规元数据；factor cell 和手工生成的 target span 留在 inference plan，正式真值位于独立 construction 树。计分器仍应通过自动首单元取得焦点，而非读取 plan 的 target span 或解析 ID 得到结果。

输入 prompt 统一要求只用来源作为事实依据。生成器只导入标准库，读取自身、设计说明和自身测试文件来记录来源哈希；没有自然数据集、历史分数、HF 模型或评分器读取路径。它由自己构造的关系规则知道逻辑结果，符合新构造控制的设计过程；不构成使用目标 benchmark gold。观察端与评价端对正式 truth 路径的隔离仍需由各自入口独立保证，此报告不代替 collector/CPU reader 的安全审查。

**结果解释的限制。** 第一，目标首句含两个并列角色断言，交换时两者一起改变；本实验不区分一个错误与两个错误的数量效应。第二，所有 filler 都来自同一固定集合且逐字复制来源，0/4/12 又采用固定前缀；负担效应也可能依赖这些具体内容与复制形式，不能推广成任意干扰内容的普遍效应。第三，目标始终第一，没有位置反平衡；它只识别这个固定接口中的回答范围×负担响应，不能证明原生成器的注意力、前缀污染或内部状态因果。第四，比赛的“sole winner→won”与签署者的近逐字模板在词法对齐难度上不同，跨族差异不能单独归因为关系本身。预先按关系族、词汇实例和方向分别报告，且不选择最佳子组，可保留这些限制。

**脚本建议。** 当前无必修数值或语义修复。若以后另建未冻结版本，可把已有测试中的 source/response flip 词袋等价检查也加入 `validate()`，利用现有 `bag()` 让生成 receipt 的自检声明更完整；这不是要求重跑当前已通过的 16 检查。另可在未来设计版本将 inference plan 的模式别名 `target` 明确写为 collector 的 `target_first_unit`，或增加明确别名说明，避免读者误解为任意人工选定范围；当前文字合同已经明确为自动首单元，别名本身没有改变本轮科学目标。若未来要声称一般负担、位置或句法效应，应另行预声明 filler 集合/顺序、目标位置与改述模板的交叉，而非在当前 48 格结果后补例调参。
