# H007：独立解释与最多两个后续入口

**结论：H007 不支持“只缩小判定范围即可挽救回答负担下的关系辨别”。H008 的无回答输入、闭集来源角色 QA 值得做一次 32 个唯一 candidate 前向的核心资格检验；这不是自然检测器晋升或新颖性结论。**

本审计仅使用已经封存并释放的 [summary](posthoc_review_v1/summary.json) 与 [48 个 cases](posthoc_review_v1/cases.json)，未调用模型、未改预测或 core/state、未恢复自然 benchmark 大标签。两文件 SHA256 与 review seal 一致；从 cases 独立重算八配对均值、正方向数量及零负担 whole/target 相等性，均与汇总一致。Review seal SHA256：`7384598dff2b43d883f911fe9f9d1fd5276df9413ac33fd3989b59795c698622`。

**不再启动一个“去后缀/去回答上下文”GPU 实验。** 在这套材料中，删除 target 后面的 R 后缀后，S、问题上下文、target 及完整 focus payload 都与对应 b=0 请求逐字相同；六排列也相同。应直接复用 H007 b=0 缓存，新增前向为零。换输出目录、协议别名或框架版本不会产生科学新信息，而 b=0 现有结果本来只有5/8正向。

## 既有工作边界

逐项核查 [P001–P031](../../research-state/prior_experiments.json)：没有记录已经执行过“完全不输入原回答的 event→person 来源 QA，以完整 source-derived candidate+EOS 联合似然作闭集重建”的同一合同。P031 的旧 proposed 标记不能抹掉之后 H003–H007 已完成的 claim verdict；真正仍未测试的是下面这项不同的 source-role 观测合同。

- **P021 保持关闭**：任意数值行列 shuffle、null-world 混合、同一分数换权重不能恢复为新方向。仅词袋不变不证明反事实语义有效。H008 不混合这些 source worlds，也不借其金融旧结果宣称改进。
- **P026 保持关闭**：原回答局部 prefix reset、原候选 repair 后未来续写似然不是新机制。H008 必须从新的 S+角色问题启动，不能偷偷保留原 R prefix，再只给候选后半段/EOS 打分。
- **P027/P028 的覆盖失败仍有效**：有限语法或现成句法解析成功不等于自然事实覆盖。新构造语法上的完整 slots 只能解决这个 toy 的接口，不是广泛自然前端。
- **[H002](../../docs/results/h002_proposal_qualification.json) 的 source-QA 核心未测试**：18次提议仅有8个无 slot 有效 frame、40个 invalid frame、4个 envelope failure；direct/blind/leaky 来源 QA 都是零调用。用程序确定完整槽位来绕开自由 offset 前端，是对未测核心的新资格合同，不是重跑提议器或宣称 H002 整体通过。

## 入口一：程序完整槽位 + 无 R 的闭集来源重建（优先 H008）

唯一新信息是 `P(完整人名及固定结束 token | S, event/role 问题)`，而不是原回答 token 的可继续性。只在本生成语法内，从**原始 S**程序解析全部 person/event 槽位和两人名池，枚举全部事件；从原始 R 定位全部对应提及仅用于之后映射。不能读构造 label 来挑错位置、筛候选或选择问题，更不能向 QA 传入 R、masked R 的另一人名、R 后缀、claimed-value 标志或 offsets。来源自身自然包含这些人名不违反盲化；约束是输入来源，而不是让字符串从 S 中消失。

最小一次实验为四个 scenario×两个来源方向×两个事件=**16 个独立 source query**，每个完整评分两个 source-derived candidate，共 **32 个唯一 candidate 前向**。48条原答都保留，通过固定映射复用这些原始观测，不能把复用写成48次独立重建。先做纯 CPU 合同检查并冻结全部 manifest，再作这一次观测；不新增随机 source shuffle、不换 prompt 扫描、不用原 b=0 再跑对照。若映射为48答风险，聚合规则必须先冻结；主资格仍是逐 query 的重建与 sourceflip，不能在看到标签后择优 max/mean 或声称联合概率。

必须先锁死四个风险点：

1. **上游泄漏**：问题、候选池及规范顺序对 responseflip/burden 字节不变；对 sourceflip 也保持同一候选顺序，例如原始两人名排序，不按“被分配者出现次序”重新排。若候选不在 prompt，也固定枚举格式。角色键与事件名来自全量 S 槽位；候选正确性映射不能作为提示字段传入。
2. **candidate-prefix 泄漏或错位**：两个人名都从同一 assistant prefix 完整评分，包含首 token、多 token 全名和与 chat template 一致的固定结束 token。严格核验拼接后的 prompt token 前缀不依赖候选，并验证因果 shift；不能只评分已给定全名后的 suffix/EOS，也不能把 target token 本身的同位置 logit 当预测。原始 token IDs、逐 token log-prob、长度及 joint log-prob 全保留。
3. **名字长度/词频先验**：joint log-prob 不是无偏真值。先冻结 sum 而不按结果选长度归一化/温度。主要看每个 event 在两种 S 下是否都排对、候选 log-odds 是否随 sourceflip 换向；同时报告对数四格差。固定候选先验在这个对数差中可抵消，但 softmax 后的风险不因此自动无偏。只有正的来源响应、却不能使候选排序反转，仍不算可靠重建。无需额外 empty-source 前向来重测既有现象。
4. **不完整候选池**：两人池穷尽性仅在当前完整来源语法中成立。多义、缺人名、未解析关系或池外可能答案必须显式 unknown，不能强制二选一后解释为自然 hallucination posterior。程序若本来能解析完整关系，就将它作为 toy 资格的透明事实基础，不包装成 LM 新发现或自然覆盖。

可证伪预测：若 claim-verdict 接口遮蔽了可用的源角色信息，新的 source-query 排名应在同一 event 的 S0/S1 中随事实绑定换向，并在所有 response/burden 映射中保持同一原始答案分布。若仍偏爱同一名字、某关系族普遍错、或前端再次失败，分别保留“来源语义能力不足/名字先验”“家族异质性”“接口未通过”，不改提示重试，不升级全任务。即使通过，也只说明这个新闭集接口提供了可用观测；没有 leaky 对照时，不能进一步声称已经证明“隐藏 claimed value 是必要原因”。

## 入口二：一个固定外部强 NLI head 的关系资格（备选诊断）

仅使用已经准备并固定 revision/七文件的 DeBERTa 外部 NLI head，读取完整 S 与同一 target T；不混合其分数，不扫模型或阈值，不把外部监督改称无监督训练。由于它不输入 R 后缀，48条中只有 **16 个唯一 (S,T)**，先 tokenizer-only 检查完整 pair≤512，再最多两批8 pair的新 head 观测；越界保留 unknown，不删源。复用现有 H007 b=0 Qwen 观察作已暴露对照，不再调用 Qwen。

若 head 对两个关系族和两个来源方向都能稳定分离，说明这些明确关系可由另一冻结仪器读出；若也失败，则不能假定一个现成 NLI head 会修复绑定。训练目标、序列化及上下文供给均变化，不能单独归因于架构，不能据 H007 已公开标签选择主方法。它与入口一是两个不同的资格问题；本轮优先入口一，head 只作固定诊断或后续独立对照，不同时发展两个加权主模块。

两入口都不授权自然任务重跑、oracle 分数、经验混合、标签校准或新确认集重命名。H007/H008 这批材料已经暴露；之后若要报告推广效能，须另外固定未用于设计的新表达/关系与完整自然覆盖合同，而不是挑出目前表现好的子族。
