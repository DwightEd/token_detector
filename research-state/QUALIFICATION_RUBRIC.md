# H002 封存后资格评价规则

本规则在首次自然样例输出产生前登记。它不训练或校准检测器，不定义风险权重、全token分数或AUROC。当前18答是探索性资格面板，不能改名为最终确认集。

## 先过完整性，再打开评价材料

评价器先验证整批观察的root seal、全部case/request、原输入哈希及有序18个ID、模型/科学协议/观察源码身份、预算和计数一致性。缺一条、部分生成、无效封存、路径越界或人口改变均拒绝。在此之前不得读取或hash `evaluation_only.jsonl`；不能只验证“有个complete.json”。

随后单独封存评价器版本与评价协议，才读取发布标注及既有人工机制预期。评价器源码可以比冻结观察器新；两者分别记录，不因此重跑模型。真实待机任务使用独立CUDA环境中94模块的旧冻结安装包，不能为增加CPU评价功能覆盖它。

## 三种不能混成一个准确率的量

- 工程/覆盖：整18答的提议、有效框架/槽位、字符覆盖、无效/未知/输出上限、空提议与成本。礼貌语不必有事实槽；字符覆盖也不等于事实覆盖。
- 来源语义：重建值是否由来源支持、角色是否正确、前提是否欠定，需结合来源逐项复核。引用存在仅证明文本成员性，答案字符串不同不自动证明冲突。
- 检测效果：还需另行冻结比较器、全token投影、重叠、未知及未覆盖行为，才能在完整六任务评价。当前观察不能直接当作已完成检测器。

## 每个自动槽位都要留下的复核轴

| 轴 | 记录什么 | 不能怎样解释 |
|---|---|---|
| 框架是否足够 | 完整、跨句指代未解、缺原问题、遗漏限定词、剩余前提错误、槽位本身不是可独立判真的语义单位 | 不能把接口省略原prompt的问题都归咎于数据集原本没有问题 |
| 可求证性 | 来源唯一支持、证据冲突、信息缺失、必须执行计算、只看到别名/改写、角色无法唯一确定 | 未知不能偷偷算正常、错误或成功弃答 |
| 输出行为 | 正确来源重建、无依据重建、合理未知、不合理未知、无效JSON/引用、输出受限 | 输出上限是序列化/覆盖限制，不单独证伪语义机制 |
| 焦点与整句 | 所核角色的关系、其他角色是否已错、完整命题支持性是否仍未成立 | 账户错但数值恰好相同不能确认整句；句级正标签中的每个词也不必为假 |
| 直接/盲/暴露值条件 | 三路来自同一自动frame/slot；保留原始请求、输出及实际token/时间成本 | 三路任务输出形式不同，不能用字符串相等直接排一个共同准确率 |

“剩余前提错误”尤其重要。例如错误对象已保留在掩码声明里，即使藏住另一个值，来源问题也可能没有唯一答案。它是H002的识别边界，不应靠替换人工正确框架修好后再记成功。未提议项留在整答分母，不只审成功槽位。

## 自然案例与构造控制分别判定

自然18答：封存后展开全部自动提议与三路观察。先看原来源是否能解该合同，再结合发布标注与既有预期事后分析。三个按输入ID哈希选择的控制不预设正/负标签。Hallu句级广播、FRED后期编辑和原始token跨度各自保留，不能重写标签让结果更好。

构造16答：输入与预期已分离封存，六对词袋相同、每对改变轴固定。构造真值与接口应输出的状态也分开：例如正确80.8推导在尚无执行器的条件下应保留未知；来源直接报告80.8则可支持。该控制不证明自然算术模块有效。只有Q1完成且接口可用才决定启动Q2，不能绕过失败的自动提议器手供槽位。

## 哪种证据改变下一动作

1. 没有有效自动框架、提议被截断或位置/引用失败：先定位前端/序列化合同，不改检测权重，也不宣称来源推理已被检验。
2. 三路都缺证据或都被同一错误前提困住：审查欠定与上下文合同。原问题已丢失和方法主动省略可用问题必须分开。
3. direct与blind同样可靠：优先保留更简单的直接核验；不能把新增提示命名当贡献。
4. blind能恢复绑定、leaky追随错误值：这是候选的观察模型输入污染证据；还需同词袋/缺证据控制、自动覆盖与成本验证，不能推断原生成器因果或总体AUROC。
5. 只有新观察模型有能力而三路无独立差异：把收益归给新观察模型/普通核验器，不归给值隔离机制。
6. 合法推导大量未知：明确当前缺执行器；后续自动类型/出处/角色提议必须独立通过资格，不能复活已否决的有限语法或用手写程序冒充自然自动方法。

每一结论保存证据位置、确定性、替代解释与下一条判别干预。不能根据某一个成功例晋升主方法；更不能对当前测试标签搜索阈值、经验权重或任务赢家。完整六任务目标与未接触确认数据的要求不变。
